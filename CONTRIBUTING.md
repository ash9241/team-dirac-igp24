# Corrections and reproductions

Please open an issue with the release version or commit, the relevant file, and the specific claim or result you are checking. For a polynomial, include its coefficient SHA-256, group/signature pair, and receipt coordinates when available.

An independent reproduction is especially helpful when it reports the exact input, commands, software versions, output, and what the check establishes. Distinguish a fresh Galois-group computation from a root-count check or a match to an archived receipt.

For code changes, keep historical evidence files intact unless correcting a documented export error. Explain changes in a new note or pull request, and update the associated provenance when an artifact changes. Do not add credentials, private conversations unrelated to IGP24, raw operational logs, or large generated caches.

The release checks are documented in [docs/reproducing.md](docs/reproducing.md). No cloud account or competition credential is needed for the default validation workflow.
